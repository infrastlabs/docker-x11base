# v-xlunch：imlib2 静态内嵌 SVG loader 构建与 Papirus 验证

> 2026-11-05 调试记录。目标：在**新 gtk 库**环境下用 `compile/src/v-xlunch/build.sh` 构建 **xlunch**（suckless 启动器）静态产包，使其**支持 SVG 图标**（Papirus 图标多为纯 SVG），配 Papirus 主题截图验证。

## 一、调试过程

### 1.1、前置检查：imlib2 静态下无任何 loader

- xlunch **不是 GTK 程序**，它用 **imlib2**（`imlib_load_image`）渲染图标，条目文件 `~/.config/xlunch/entries.dsv`（**分号分隔**：`title;icon_path;command`）。
- imlib2 1.7.4（sourceforge 下载）+ xlunch 0.8.4（gitee fk-xlunch）构建成功，但 **图标全黑屏**——连 PNG 都不显示。
- 根因：imlib2 的 loader 全部走 **dlopen**（`loaders.c` 的 `__imlib_ProduceLoader` 用 `dlopen`+`dlsym` 找 `load`/`load2`/`save`/`formats`），静态/musl 下没有 `.so`，`dlopen` 返回 NULL，**所有 loader 失效**。
- imlib2 1.7.4 的 imlib2_loaders 只有 ani/eet/xcf，**无 svg loader** → 必须手写。

### 1.2、手写 SVG loader（loader_svg.c）

- 新建 `/tmp/imlib2/src/modules/loaders/loader_svg.c`（**87 行**），用 **librsvg**：
  - `rsvg_handle_new_from_data` 解析 SVG → `rsvg_handle_get_dimensions` 取宽高 → `rsvg_handle_render_cairo` 渲染到 cairo `CAIRO_FORMAT_ARGB32` surface → `memcpy` 到 `im->data`（`__imlib_AllocateData`）。
  - `DATA32` 为 ARGB（小端 BGRA），与 cairo ARGB32 兼容，可直接 memcpy；`SET_FLAG(im->flags, F_HAS_ALPHA)`。
- **关键坑**：不能写 `im->format = "svg"`——imlib2 加载成功后**自动**从 loader 的 `formats[0]` `strdup` 设置 `im->format`（`image.c:552-553`），且失败清理路径会 `free(im->format)`（`image.c:546`）；字符串字面量被 free 会崩溃。删除该行，依赖自动 strdup。
- include 需 `#include <librsvg/rsvg.h>`（pkg-config cflags 给 `-I.../librsvg-2.0`，`<rsvg.h>` 找不到）。

### 1.3、静态内置 loader 机制（musl/dlopen 下唯一可行）

- 上游 loader 源码用宏**重命名符号**避免冲突，编译进 libImlib2.a，并补丁 `__imlib_LoadAllLoaders` 跳过 dlopen 手动构造 `ImlibLoader`：
  - 编译：`-Dload2=png_load2 -Dsave=png_save -Dformats=png_formats`（png 同理 svg），生成 `png.o`/`svg.o`。
  - 补丁 `loaders.c`：在 `if (loaders) return;` 后插入**完整内置块**——`extern` 声明 `png_load2/png_save/png_formats/svg_load2/svg_formats`，`malloc` 两个 `ImlibLoader`（`file="png"`、`file="svg"`），`png->next = svg; loaders = png;`。
  - `ar r /usr/local/lib/libImlib2.a loaders.o png.o svg.o && ranlib`。
- **注意**：原始 `loaders.c` **没有** `loaders = bl;`（png 内置块是我手工加的，不在上游）；补丁须**整体插入**（锚点 `if (loaders)\n      return;`），不能只加 svg。

### 1.4、链接依赖（librsvg 链条）

- imlibtest/xlunch 静态链接需完整依赖，用 `--start-group` 解循环引用：
  - `pkg-config --static --libs librsvg-2.0 cairo pangocairo`。
  - **librsvg 用到 pango 但 .pc 未声明** → 需显式 `pangocairo`（含 pango/pangoft2/harfbuzz/fribidi/graphite2/Xft）。
  - **librsvg 用到 libxml2 + libcroco**（css）但 .pc 未声明 → 手动 `-lxml2 -lcroco-0.6`。
  - **libxml2 用到 lzma**（xzlib.c）→ `apk add xz-dev`（`-llzma`）。
  - **gdk_pixbuf 的 tiff/zstd 支持非必需**且无 `libzstd`/`libtiff` → 过滤 `-lzstd -ltiff`（不引用则不拉取对象）。
  - 最终 imlibtest：39.4M 静态；**PNG `LOADED 1x1`、SVG `LOADED 48x48`**，内置 loader 生效。

### 1.5、build.sh 收编

- `compile/src/v-xlunch/build.sh` 修改：
  1. `imlib2()` 安装后追加**内置 loader 段**：`apk add librsvg-dev cairo-dev pango-dev xz-dev`、拷贝 `loader_svg.c`、python 幂等补丁 `loaders.c`、`xx-clang` 编译 `png.o`/`svg.o`/`loaders.o`、`ar r libImlib2.a`。
  2. `xlunch()` 链接改 `-Wl,--start-group ... -lImlib2 $RSVG_LIBS -lxml2 -lcroco-0.6 ... -Wl,--end-group`。
  3. **`SCRIPT_DIR` 必须在函数外顶部计算**（imlib2() 内 `cd /tmp/imlib2` 后 `dirname $0`=`.` 解析到错误目录）。
- 端到端 `bash build.sh full` 通过：`loaders.c patched`、xlunch 链接成功、`xx-verify --static` 通过、产包静态。

### 1.6、runtime 验证（Papirus SVG 图标）

- runtime 容器 `docker-hdmi-desktop-desktop-1`，Xvnc `:462`，entries.dsv 6 项指向 `/usr/share/icons/Papirus/48x48/apps/*.svg`。
- xlunch 全屏截图 `1280×800`：深灰背景 + **一行 6 个彩色 Papirus SVG 图标** + 白色标题文字；像素分析 `(255,136,0)` 橙（Firefox）、`(74,150,225)` 蓝（VLC/Chromium）可见。
- **SVG 图标渲染成功**（imlib2 内置 svg loader 生效）。
- 截图：`docs/img/tmp/v-xlunch/xlunch-papirus-svg.png`。

> **订正（2026-11-05 补 PNG 验证）**：**PNG 同样支持**。imlib2 内置 loader 含 **png + svg** 两个；
> `imlibtest` 实测 PNG `LOADED 1x1`、SVG `LOADED 48x48`。混合 entries（前 3 项 hicolor PNG：
> feh/geany/gvim，后 3 项 Papirus SVG：firefox/vlc/gimp）截图分段分析：
> seg0-2（PNG）与 seg3-5（SVG）均有彩色像素，**PNG 与 SVG 图标都渲染成功**。
> 截图：`docs/img/tmp/v-xlunch/xlunch-png-svg-mix.png`。
