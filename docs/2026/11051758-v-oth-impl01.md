## 一、engrampa 静态构建调试（2026-11-05 完成：产物 12.6M 静态验证通过）

### 1、环境与版本

- **构建容器**：`builder-obox`（musl，`alpine-builder-gtk224`）。
- **源码**：`git clone --depth=1 --branch=v1.14.1 $GITHUB/mate-desktop/engrampa`（2016-05 发布，
  GTK2 最后一版；1.16.0 起纯 GTK3）。
- **依赖就位（box 实测）**：`gtk+-2.0`（u-gtk 2.24.33）、`glib-2.0/gthread-2.0/gio-unix-2.0`
  （u-gtk 静态树）、`librsvg-2.0`（v-tint2）、`libxml2/expat/freetype/xcb/X11/Xinerama/Xfixes/Xrandr`
  （apk 静态库）。
- **构建时工具**：需 `mate-common`（mate-autogen）、`yelp-tools`（yelp-build）、`itstool`（首次未装）。

### 2、构建调试逐轮

**轮1——autogen.sh 缺 mate-autogen/yelp-build**
- 现象：`./configure: not found`（autogen.sh 静默失败未生成 configure）。
- 根因：engrampa `autogen.sh` 硬性 `which mate-autogen`（mate-common）+ `which yelp-build`
  （yelp-tools），缺失即 exit 1。
- 解决：`apk add mate-common yelp-tools`（Alpine 有，mate-common-1.26.0-r0 / yelp-tools-41.0-r0）。

**轮2——configure 缺 itstool**
- 现象：`configure: error: itstool not found`。
- 解决：`apk add itstool`（2.0.7）。

**轮3——链接缺 -lintl**
- 现象：`undefined reference to libintl_textdomain/gettext/bindtextdomain/...`（glib ggettext 拉入）。
- 解决：LIBS 组加 `-lintl`。

**轮4——g_ptr_array_copy 与系统 glib 冲突**
- 现象：`actions.c: conflicting types for 'g_ptr_array_copy'`（系统 glib-2.0/garray.h 三参声明）。
- 根因：engrampa 1.14.1 自带**单参** `g_ptr_array_copy(GPtrArray*)`（glib-utils.h:69 声明 +
  glib-utils.c:572 实现），与系统 glib≥2.32 的**三参** API 冲突（engrampa 要求 glib≥2.32，自带实现冗余）。
- 解决：该函数为 **dead code**（全 src 无调用）→ patch 删除声明+实现
  （`compile/src/v-engrampa/engrampa-1.14.1-glib-g_ptr_array_copy.patch`，build.sh 幂等 apply）。

**轮5——libtool 拆散 --start-group（关键 rootcause）**
- 现象：主程序链接 `undefined reference to xcb_connect/xcb_get_setup/...` + `FT_*` + `XML_*`。
- 根因（`make V=1` 验证）：`libtool --mode=link` 把 `-Wl,--start-group/-Wl,--end-group`
  **拆开放最前且中间为空**，start-group 后的库全部被移到 end-group 之后 → **group 完全失效**，
  静态循环依赖（gtk↔X11↔xcb、Xft↔freetype、xml2↔expat）无法解析。
- 解决：**仿 geany 手动静态链接**——make 只编译 objects + commands 辅助二进制（已成功），
  engrampa 主程序用 `xx-clang -static` 直接链（objects + `.libs/libeggsmclient.a` +
  `-Wl,--start-group ... -Wl,--end-group` 生效）。
- 注意：make 时 `FR_LIBS=""`（pkg-config 非 static 库在 LDADD 且 group 外，会让 gtk 依赖断）。

**轮6——旧 C tentative definitions 重复符号**
- 现象：`multiple definition of ForceDirectoryCreation/WindowList`（main.o 与 fr-init.o）。
- 根因：xx-clang 12 默认 `-fno-common`，旧 C 代码的 tentative definition（跨 .o 同名全局变量）冲突。
- 解决：手动链接加 `-Wl,--allow-multiple-definition`。

### 3、最终产物与验证

- **产物**：`/usr/local/static/engrampa/bin/engrampa`（12.6M，静态）。
- **file**：`ELF 64-bit LSB executable, x86-64, ... statically linked, stripped`。
- **ldd**：`Not a valid dynamic program`。
- **xx-verify --static**：PASS。
- **手动链接段 undefined reference**：0。
- **data**：`make install-data` 装 `libexec/engrampa/isoinfo.sh` 等（ui/icons/gschema/help 随
  install-data）。

### 4、结论与后续

- **engrampa 1.14.1 静态构建成功**（GTK2 最后一版，无真缺口，仅需 `--disable-caja-actions`）。
- **关键经验**：
  - engrampa（MATE）autogen 需 mate-common/yelp-tools/itstool（apk 装）。
  - **libtool 会拆散 `--start-group`**（静态循环依赖失效）→ GTK2 静态链接**必走手动 xx-clang**，
    与 geany 同法。
  - 旧 C tentative definitions 需 `-Wl,--allow-multiple-definition`。
- **待办**：①GUI 实跑验证（Xvnc，按 AGENTS.md 3.1 套路）；②后续可补 `--with-gtk` 相关或
  icon 主题验证；③build.sh/vers.txt/patch 落仓（单独 commit）。

### 5、Xvnc 效果截图与踩坑记录（2026-11-05，Greybird+Papirus 效果图）

> 需求：hdmi 容器（`docker-hdmi-desktop-desktop-1`，Ubuntu 22.04 + TigerVNC 1.13.1）内
> Xvnc 跑，配 **Greybird 主题 + Papirus 图标** 出效果图；scrot 截图须"看得到效果"
> （截有主题内容的屏，非空屏）。本节记处理过程 + 踩坑/注意项。

#### 1、效果图两个必要条件（engrampa 显示 Papirus）

**前提**：Papirus 是**纯 SVG 图标集**（实测 509 svg / 0 png）；静态 gdk-pixbuf 默认
只内置 PNG/JPEG，**无 SVG 解码器** → Papirus 图标解不了、不显示。

1. **编译侧——必须在 `builder-awe`**：
   - awe 的 `/usr/local/lib/libgdk_pixbuf-2.0.a` 是 meson 构建
     `-Dbuiltin_loaders=png,jpeg,svg`（`gdk-pixbuf-io.o` 有 `U _gdk_pixbuf__svg_fill_vtable`，
     `nm` 实见）→ 内置 svg loader；配 `/usr/local/lib/librsvg-2.a`(2.40.21) +
     `libcroco-0.6.a`。链接 `-L/usr/local/lib` + LIBS0 含 `-lrsvg-2 -lcroco-0.6`。
   - **obox 的 gdk_pixbuf 是 Alpine 系统包（无 svg builtin），编译产物图标照样不显示**。
2. **运行时侧——gtkrc 必须显式设 `gtk-icon-theme-name`**：
   - Greybird `/usr/share/themes/Greybird/gtk-2.0/gtkrc` **没有** `gtk-icon-theme-name`
     → GTK 用默认 hicolor（非 Papirus），图标灰/空白。**此坑与"与 gtkrc 加载路径有关"**。
   - 修复：wrapper gtkrc `gtk-theme-name="Greybird"` + `gtk-icon-theme-name="Papirus"`，
     启动时 `GTK2_RC_FILES=/tmp/wrapper.gtkrc`。

**效果**：engrampa 打开含 12 种类型文件的 tar.gz，文件列表 mimetype 图标显示 Papirus
彩色（(54,172,163)/(192,54,48)/(57,116,225) 等特征色，icon 列 14 彩色行）。

#### 2、scrot 截图"看得到效果"的做法

- scrot 是 CLI 截图工具（无 GUI）。要"看得到效果"：先让屏幕有**主题内容**
  （openbox + Greybird/Papirus 的 engrampa 窗口），再 `scrot` 截整屏 → 截图里就是
  主题化界面，即 scrot 能力证明。产物 9.7M 版本（自建 imlib2）截 1280x800 成功。
- 窗口特写：`scrot -u`（聚焦窗口）需先 `xdotool windowactivate <id>` 激活。

#### 3、踩坑 / 注意项清单

- **`pkill -f <路径>` 自匹配杀外层 shell**：`docker exec ... bash -c 'pkill -f /tmp/engrampa'`
  会杀到外层 `bash -c`（命令行含该字符串）→ exit -1/143。改用显式 PID 或按
  `comm==engrampa` 过滤再 kill。
- **`docker exec` 输出被吞**：命令含后台/`nohup`/`pkill` 时，后续 `echo` 常不回显
  （exit 0 但无输出）。对策：输出重定向到文件 + 单独一次 exec `cat`/`ls`（AGENTS.md 已知）。
- **`docker cp` 并发时序**：截图命令后立刻 `docker cp` 会报 `No such container:path`
  （文件尚未写完/未落盘）。对策：`sleep 1` + 单独 exec cp，失败则重跑。
- **awe 容器 `/src` 是旧挂载**：无 `v-engrampa`/`v-scrot`（obox/宿主有）。对策：构建文件
  `docker cp` 到容器 `/tmp/<comp>-build/` 再跑（build.sh 的 `source /src/common.sh` 仍可用）。
- **宿主 `/tmp` 不可写**（root:root，磁盘近满）→ 中转用 `~/.tmp-verify/`。
- **engrampa autogen 依赖**：`apk add mate-common yelp-tools itstool`（mate-autogen/
  yelp-build/itstool），否则 `./autogen.sh` 失败。
- **configure 仍报 libcaja-extension**：`--disable-caja-actions` 后 caja-extension 依赖
  仍被查（configure 未 `|| exit`，容错继续）→ 产物可用（caja 相关未编译），非致命。
- **Greybird gtkrc 有 `engine "murrine"` 多处**：静态 GTK dlopen murrine 引擎失败
  （`Unable to locate theme engine` 警告），但 style 配色仍生效（窗口灰 #CECECE 正确）。
- **Xvnc 探针每次换新 display 号**（:322 起，防 root 残留壁纸污染）；用完清
  `/tmp/.X<NN>-lock` + `/tmp/.X11-unix/X<NN>`（AGENTS.md 3.1）。

#### 4、headless 用户直接跑（Greybird+Papirus 参数实测）

- **场景**：hdmi 容器内以 `headless`（uid=1000，`HOME=/_ext/home/headless`）直接跑静态
  engrampa，不 root。实测通过（窗口 `demo2.tar.gz [read only]`，sat 1572 / 14 彩色图标行，
  与 root 跑一致）。
- **gtkrc 加载路径处理**（对应"与 gtkrc 加载路径有关"）：Greybird `gtk-2.0/gtkrc` **无
  `gtk-icon-theme-name`** → 落默认 hicolor。不改系统主题，用 **wrapper gtkrc** 重定向
  （`GTK2_RC_FILES` 是 GTK2 最高优先 rc 路径）：
  ```
  gtk-theme-name = "Greybird"
  gtk-icon-theme-name = "Papirus"
  ```
- **必带参数**（缺一不可）：
  | 参数 | 作用 |
  |---|---|
  | `GTK2_RC_FILES=/tmp/greybird-papirus.gtkrc` | 设 Greybird + Papirus（**没有 → hicolor 默认图标**） |
  | `GTK_DATA_PREFIX=/usr` | 找 `/usr/share/themes` + `/usr/share/icons` |
  | `HOME=<headless home>` | icon cache 可写 |
  | `DISPLAY=:NNN` | 连 Xvnc |
  | `/tmp/engrampa` | **awe 编译版**（内含 svg loader；obox 版图标不显示） |
- **实测命令**：
  - 方式 A（脚本，避免嵌套引号坑）：`/tmp/run-engrampa-hl.sh` export 上述变量后
    `exec /tmp/engrampa /tmp/demo2.tar.gz`，`runuser -u headless -- /tmp/run-engrampa-hl.sh`。
  - 方式 B（su 单行）：`su - headless -s /bin/bash -c 'DISPLAY=:322 HOME=... GTK2_RC_FILES=...
    GTK_DATA_PREFIX=/usr GTK_ICON_THEME=Papirus /tmp/engrampa /tmp/demo2.tar.gz'`。
- **注意**：归档若 root 所有 → 窗口标题带 `[read only]`（不影响图标）；读写需
  `chown headless:headless <归档>`。headless 跑不依赖 root（Xvnc `-ac` 关访问控制）。

#### 5、静态 engrampa 无中文（gettext LOCALEDIR 坑）——2026-11-05

> 现象：hdmi headless 手动跑，静态 engrampa **无中文**（英文菜单）；**apt 版有中文**；
> **geany 静态 1.34 有中文**。

- **根因（确凿）**：engrampa `config.h:79` `#define LOCALEDIR "/usr/local/static_temp1/share/locale"`
  （configure 默认 `localedir=${datarootdir}/locale`，prefix 为 oneBuild 的 static_temp1 staging）；
  `src/main.c:292` `bindtextdomain (GETTEXT_PACKAGE, LOCALEDIR)`。**hdmi 无此路径** →
  gettext 找不到 `.mo` → 英文。（geany 静态有中文 = 其 LOCALEDIR 指向系统路径 / 构建完整
  生成 `.mo` 且能找到。）
- **修复方案**：
  - **方案 B（免重编，已实测）**：hdmi 建 LOCALEDIR 路径 + 放 `.mo`：
    `mkdir -p /usr/local/static_temp1/share/locale/zh_CN/LC_MESSAGES` + 放 `engrampa.mo`
    （用源码 `msgfmt po/zh_CN.po` 生成，32270B，比 apt 版更匹配 1.14.1）。跑时
    `LANG=zh_CN.UTF-8 LC_ALL=zh_CN.UTF-8`。实测菜单栏非bg 1186(英)→4415(中)，`.mo` 生效。
  - **方案 A（更干净，需重编）**：engrampa configure 加 `--localedir=/usr/share/locale`
    → `LOCALEDIR=/usr/share/locale`，直接找系统 `.mo`（hdmi `/usr/share/locale/zh_CN/
    LC_MESSAGES/engrampa.mo` 已在）。
- **注意**：`TEXTDOMAINDIR` 对静态 engrampa **无效**（它是 gettext **工具**变量，非
  libintl 运行时；`bindtextdomain` 用编译时 LOCALEDIR，不读该 env）。勿被误导。
- **中文渲染**：LANG=zh_CN 与 LANG=C 窗口白色比一致（0.225 vs 0.225），渲染无异常；
  中文菜单像素更多属正常。

> **订正（2026-11-05）——方案 A 需 configure.ac 补丁**：`--localedir` **单独不够**。
> engrampa `configure.ac` 硬编码 `LOCALEDIR` 为 `${ac_default_prefix}/${DATADIRNAME}/locale`
> （prefix=NONE 时）或 `${prefix}/${DATADIRNAME}/locale`，**忽略 `--localedir`** → config.h
> 仍指向 static_temp1。**必须再补 configure.ac**：两分支改
> `AC_DEFINE_UNQUOTED(LOCALEDIR, "${localedir}", [Locale dir])`（autoconf 标准目录变量
> `localedir` 由 `--localedir` 赋值，默认 `${datarootdir}/locale`）。
> `compile/src/v-engrampa/build.sh` 已加 `--localedir=/usr/share/locale`，并在 `./autogen.sh`
> **前**应用补丁 `engrampa-1.14.1-localedir.patch`（autogen 重新生成 configure 才生效）。

- **方案 A 实测结果（2026-11-05）**：重编后 `config.h:79` LOCALEDIR=`/usr/share/locale`；
  产物静态链（xx-verify OK，`file`=statically linked, stripped）；hdmi 放 `.mo` 到
  `/usr/share/locale/zh_CN/LC_MESSAGES/engrampa.mo`，headless 跑 `LANG=zh_CN.UTF-8`：
  窗口标题 `demo2.tar.gz [只读]`（中文），菜单栏非bg **4423**（≈方案 B 中文 4415）；
  LANG=C 对照标题 `[read only]`、菜单非bg **3631**（菜单文本行 ~30-82px/行 vs 中文
  ~112-143px/行，CJK 更密）——**方案 A 生效，静态版中文**。
- **lxtask/pcmanfm 同坑（2026-11-05 确认）**：`strings` 显示 lxtask
  `LOCALEDIR=/usr/local/static/lxde/share/locale`、pcmanfm
  `LOCALEDIR=/usr/local/static/pcmanfm/share/locale`——均指向容器外路径（hdmi 无），
  **同样无中文**。是否按方案 A 修（`--localedir` + configure.ac 补丁）**待用户指示**，
  先记录此坑。

> **订正（2026-11-06）——lxtask/pcmanfm 均已修复**：两者 `bindtextdomain` 用 **`PACKAGE_LOCALE_DIR`**

- **构建容器**：`builder-obox`（musl）。源码 `resurrecting-open-source-projects/scrot` **1.12.1**
  （2019-12，最后 1.x）。
- **选型**：匹配现有 **imlib2 1.7.4**（v-feh/xlunch 已用）；scrot 2.0.0 需 imlib2>=1.11.0
  不满足故不上。
- **依赖**（deps.pc `Requires: x11 imlib2 xcomposite xext xfixes xinerama`）：box pkg-config 全 OK

- **构建时工具**：`autoconf-archive`（AX_APPEND_COMPILE_FLAGS，首次未装）。

### 2、构建调试逐轮

**轮1——github clone 网络失败**
- 现象：`fatal: unable to access 'https://github.com/.../scrot': Failure when receiving data from the peer`。
- 解决：改用 **ghfast.top 代理** `https://ghfast.top/https://github.com/<user>/<repo>.git`
  （可靠，memory 经验）。

**轮2——部分 clone 缺 autogen.sh**
- 现象：`./autogen.sh: not found`。
- 根因：首次 clone 部分失败/中断，`/tmp/scrot` 只留 `.git` 无源码文件（skip-clone 误判）。
- 解决：`rm -rf` 后经 ghfast.top **干净完整 clone**（有 autogen.sh）。

**轮3——链接缺 -lxcb-util / -lXi**
- 现象：`ld: cannot find -lxcb-util` / `cannot find -lXi`。
- 根因：Alpine **无 xcb-util 主库 dev 包**；但 `nm /usr/lib/libImlib2.a` 实测**无 xcb_aux_* /
  XInput undefined** → imlib2 1.7.4 **不需要**这两库（v-feh deps1/2/3 为保守全列，含冗余）。
- 解决：从 LIBS 去掉 `-lxcb-util`、`-lXi`。

### 3、最终产物与验证

- **产物**：`/usr/local/static/scrot/bin/scrot`（2.4M，静态）。
- **file**：`ELF 64-bit LSB executable, x86-64, ... statically linked, stripped`。
- **ldd**：`Not a valid dynamic program`；**xx-verify --static**：PASS；**undefined**：0。
- **data**：`make install` 装 `share/doc/scrot`（AUTHORS/README/FAQ/scrot.png 等）+ `share/man/man1/scrot.1`。

### 4、结论与后续

- **scrot 1.12.1 静态构建成功**，**零新依赖**（imlib2 1.7.4 + X 库全就位）。
- **关键经验**：github clone 时通时断 → 一律 ghfast.top 代理；Alpine 无 xcb-util 主库 dev 包，
  imlib2 1.7.4 实不需 xcb-util/Xi（nm 验证）。

### 5、Xvnc 实跑验证与 imlib2 根因修复（2026-11-05 订正）

> **订正（2026-11-05）**：原 2.4M 产物 CLI 实跑**失败**，根因在 imlib2 链接，修复后 9.7M。
> 验证环境：`docker-hdmi-desktop-desktop-1`（Ubuntu 22.04，TigerVNC 1.13.1）Xvnc `:311`
> （1280x800x24，`-SecurityTypes None -ac`），按 AGENTS.md 3.1 spawn 模板。

**现象（实跑失败）**
- `scrot /tmp/x.png` → `scrot: failed to save image`；png/jpg/bmp **全格式失败**（rc=1）。
- 对照组系统 `/usr/bin/scrot` 同环境截图成功（1280x800 PNG）→ 非 X 环境问题，是我们二进制问题。

**根因（链错 imlib2）**
- 原 build.sh 链 `-lImlib2` 但**没加 `-L/usr/local/lib`** → 落到 **Alpine 系统
  `/usr/lib/libImlib2.a`**（2021 包，443K）。
- `nm /usr/lib/libImlib2.a | grep __imlib_Format` = **0 个符号**：Alpine 静态包**不含
  format handler**（png/jpeg/bmp 写入器是 dlopen 插件，不进 .a）→ 运行时
  `imlib_save_image` 无 handler → save 失败。
- 佐证：修复后 `nm /usr/local/lib/libImlib2.a` 有 5 个 loader 符号
  （png_save/jpeg_save/png_formats/jpeg_formats/svg_formats）。

**修复（build.sh）**
1. `b_deps` 先自建 imlib2：`apk add libjpeg-turbo-static jpeg-dev` +
   `bash /src/v-xlunch/build.sh imlib2`（v-xlunch 的 imlib2 函数把 png/jpeg/svg
   loader 用 `ar r` 内嵌进 `/usr/local/lib/libImlib2.a`，611K）。
2. 链接加 `-L/usr/local/lib`（优先自建库）；LIBS 补 `$RSVG_LIBS -lxml2 -lcroco-0.6`
   （svg loader 需 librsvg/cairo/glib/pango，同 feh 模式）。

**产物（修复后）**
- `/usr/local/static/scrot/bin/scrot` **9.7M**（含 librsvg/cairo/pango/glib 静态链）。
- `file`：`statically linked, stripped`；`xx-verify --static`：PASS；`ldd`：`Not a valid dynamic program`。

**实跑验证（通过）**
- `scrot /tmp/our-scrot.png` → rc=0，`PNG image data, 1280 x 800, 8-bit/color RGB`。
- **验证结果**：scrot 截图成功（1280x800 PNG），engrampa 窗口 "Archive Manager" 正常显示
  （效果图不落 md，按用户要求仅作推送附件）。
- **经验**：静态链 imlib2 必须用**自建**（含内嵌 loader）而非 Alpine 系统 .a，否则
  save 全挂；共享 libImlib2.a 嵌 svg.o 会连带 librsvg/cairo 静态链（凡链 imlib2 的
  组件都要带 `$RSVG_LIBS`）。

### 3、gconf 打补丁去掉（keyfile shim）

#### 1、思路：header-only `src/gconf-shim.h` 替换 libgconf

- gsm 用 `GConfClient*`（ProcData.client）+ gconf_client_get/set_*、notify_add、dir_exists、get_list、
  entry/value 访问器。**不改 24 处调用点**，用同名 API 的 **GKeyFile 实现**顶替。
- 偏好存 **`~/.config/gnome-system-monitor/procman.ini`**（GKeyFile group `procman`，key = gconf 路径
  去前导 `/`）。值带类型前缀 `i:`/`b:`/`s:`/`l:`（int/bool/string/int-list），reload 时类型无歧义。
- **notify_add 保持生效**：set_* 后同步触发已注册回调（GConfEntry/GConfValue 合成），config 字段
  实时更新——与 libgconf 行为一致（gsm 的 setter 只写 gconf，靠 notify 更新 ProcData.config）。
- 函数清单：`gconf_init`(no-op)、`gconf_client_get_default/add_dir/suggest_sync/dir_exists`、
  `get_int/bool/string/list`、`set_int/bool/string/list`、`notify_add/remove`、
  `gconf_entry_get_key/value`、`gconf_value_get_bool/int/string/free`、`GCONF_VALUE_INT`、
  `GCONF_CLIENT_PRELOAD_NONE`。
- **configure.in + 预生成 configure** 均去掉 `gconf-2.0` / `dbus-glib-1`（PKG_CHECK_MODULES 模块串
  sed 8 处）+ `AM_GCONF_SOURCE_2`。gconftool-2 schema 检查非致命（反引号替换，留空）。

#### 2、dbus-glib 实际不用

- gsm 单实例是 **Unix socket**（`src/bacon-message-connection.c`），无任何 dbus/dbus-glib 代码引用
  （`grep -ri dbus src/`=空）。→ 从 PKG_CHECK_MODULES 去掉，免建 libdbus-1.a。

#### 3、补丁文件 `gsm-gconf-keyfile.patch`（8 文件 673 行）

`configure`、`configure.in`、`src/gconf-shim.h`(新)、`src/openfiles.cpp`、`src/procman.cpp`、
`src/procman.h`、`src/smooth_refresh.cpp`、`src/smooth_refresh.h`。`git apply -p1` 干净。

#### 4、其他小补丁（在 patch 内）

- `src/procman.cpp`：删 `gconf_init(argc, argv, NULL)`（shim 里是 no-op；且调用签名在 musl 下与声明不符）。
- `src/openfiles.cpp`：`NI_IDN` 换 `0`（getnameinfo 的 GNU 标志，**musl 未定义**→编译错；IDN
  解析是可选增强，弃用）。

### 4、构建要点

#### 1、configure（非 -static LDFLAGS，pavucontrol 式）

```sh
export LDFLAGS="-Wl,--strip-all -Wl,--as-needed"
export PKG_CONFIG_PATH=/usr/local/static/gtop/lib/pkgconfig:/usr/local/static/wnck/lib/pkgconfig:$PKG_CONFIG_PATH
./configure --enable-static --disable-shared --prefix=/usr/local/static/gsm
```

- configure 测试程序需非 -static（否则 AC_* 链接静态 glib 缺 -lpcre 等失败）。
- `CXXFLAGS` **必须 `-std=c++11`**：glibmm-2.48/sigc++ 头要求 C++11（`-std=c++98` 报
  "requires C++11"）；configure.in 强制 `-std=c++98` → make 时覆盖。

#### 2、make（只取 .o，链接手动）

```sh
make -j$(nproc) CFLAGS="-Os -fomit-frame-pointer" CXXFLAGS="-Wall -std=c++11 -Os -fomit-frame-pointer"
```

- 25 对象（22 .cpp + 3 .c），无编译错。make 默认目标的链接失败是预期（静态链缺库）。

#### 3、静态链（xx-clang++ -static，19.3M）

- 基础同 v-pavucontrol `LIBS0`（gtk2 全套 + X/pango/freetype/harfbuzz/cairo...），

  `libgcc_s.a` 兜底（同 §3.5 坑 4）。
- **验证**：`file`=ELF x86-64 **statically linked, stripped**；`xx-verify --static` PASS；

### 2、构建调试逐轮

- **依赖补建（b_deps）**：8 包每包 `autoreconf(如无 configure)`→`configure --enable-static --disable-shared --prefix=/usr/local`→`make -j LIBS="-lXau -lXdmcp"`→`make install`，逐包校验 `.a`，任一失败 exit 1。
  - **坑（b_deps 吞错）**：`oneBuild` 用 `set +e`，xcb-util-image 测试程序缺 `-lXau -lXdmcp`（xcb 传递静态依赖）导致 `make` 失败被吞 → ①`make LIBS="-lXau -lXdmcp"` 补齐；②b_deps 每步 `|| exit 1` 不再吞。
- **第 1 轮（glib 版本）**：rofi 2.0.0 要求 `glib>=2.72`，容器 Alpine 3.15 仅 2.70.5（apk 无网络升级）→ `sed glib_min_minor=72→70`，编译实证通过。
- **第 2 轮（子模块缺失）**：github tarball 不含 `subprojects/libgwater`/`libnkutils`（git 子模块，目录为空）→ 宿主 `git clone --recurse-submodules -b 2.0.0` 取固定提交 `d86f990/2f220a4`，填回。
- **第 3 轮（meson feature 选项）**：meson 0.59 只认 `enabled/disabled/auto`，不认 `true/false` → 改 `-Dwayland=disabled -Dxcb=enabled`。
- **第 4 轮（flex/bison 缺失）**：rofi 需 flex+bison 生成 `lexer/theme-{lexer,parser}` → 宿主下载 Alpine 3.15 `flex-2.6.4-r2`/`bison-3.7.6-r0` apk，`apk add --allow-untrusted`。
- **第 5 轮（zlib 缺失）**：`libz.a`（png/fontconfig 传递依赖）不在容器 → `zlib-dev-1.2.12-r3` apk 安装（装到 `/lib/libz.a`）。
- **第 6 轮（meson 解析 .so）**：meson 把 pkg-config 的 `-lfoo` 默认解析成 `.so` 全路径（即使 `--static`），`-static` 报 `attempted static link of dynamic object` → **pkg-config 包装器**把 `--libs` 输出里的 `-lfoo` 统一换成存在的 `.a` 绝对路径。
- **第 7 轮（XGetXCBConnection）**：startup-notification `.pc` 未声明 `libX11-xcb.a` → 包装器安全网统一附加 `/usr/lib/libX11-xcb.a`。
- **第 8 轮通过**。
- 构建命令：
  - `b_deps`：`sh build.sh b_deps` → 8 包补建。
  - `rofi`（meson）：`meson setup /tmp/rofi-build -Dwayland=disabled -Dxcb=enabled -Dimdkit=false -Dcheck=disabled -Dprefix=/usr/local/static/rofi -Dc_args="$CFLAGS" -Dc_link_args="-Wl,--as-needed -static -Wl,--strip-all -L/usr/local/lib"`；`ninja -C /tmp/rofi-build`；`ninja -C /tmp/rofi-build install`。
  - **静态链关键**：`PKG_CONFIG` 指向自写包装器（`pkg-config --static` 且把 `-lfoo` 换成存在的 `.a` 绝对路径 + 附加 `/usr/lib/libX11-xcb.a` 安全网）；meson 默认把 libs 包进 `--start-group/--end-group`；`-static` 强制静态。
