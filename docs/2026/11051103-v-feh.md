# v-feh：imlib2 静态内置 loader 支持与 feh 用不了修复

> 2026-11-05 记录。hdmi 环境现有静态编译 **feh 用不了**（imlib2 加载图片失败）。目标：参照 xlunch 的 imlib2 内置 loader 方案，让 feh 静态二进制能正常加载"必须"格式（**png/svg/jpeg**），并修复构建脚本。

## 一、调试过程

### 1.1、hdmi 现有 feh 问题回顾

- hdmi（`docker-hdmi-desktop-desktop-1`）现有 `/usr/local/static/feh/bin/feh`（**1.66M**，`statically linked`，Feb 6 2026 构建）。
- `--version`/`--help` 能启动（不段错误），但**加载图片全失败**（Xvnc `:462` 实测）：
  ```
  feh WARNING: <图> - No Imlib2 loader for that file format
  feh ERROR: Unable to load image <图>
  rc=2
  ```
  连 **PNG**（`feh.png`/`geany.png`）都报 `No Imlib2 loader`。
- **根因**：hdmi feh 链接的是**旧 `libImlib2.a`**（11-05 之前）。imlib2 的 loader 全走 **dlopen**（`loaders.c` `__imlib_ProduceLoader`），静态/musl 下无 `.so` → **所有 loader 失效**（与 xlunch 旧黑屏同源）。
- 11-05 已给新 `libImlib2.a` 加**内置 png+svg loader**（xlunch 用，已验证），但 hdmi feh **未用上**。

### 1.2、需要支持的格式与支持方案

#### 1.2.1、需要支持的格式（feh 看图/壁纸常见）

> **范围收敛（见 2.1）**：只实现"必须"的 **PNG、SVG、JPEG**；其余（gif/bmp/tiff/webp）暂不做。

feh 用 **imlib2** 加载图片，支持格式 = imlib2 核心 loader（`/tmp/imlib2/src/modules/loaders/` 自带源）：

| 格式 | loader 源 | 外部依赖 | 容器静态库 | 优先级 |
|---|---|---|---|---|
| PNG | `loader_png.c` | libpng | `/usr/lib/libpng.a` ✅ | **必须**（已内置） |
| SVG | `loader_svg.c` | librsvg/cairo/glib | `/usr/local/lib/librsvg-2.a` ✅ | **必须**（已内置） |
| JPEG | `loader_jpeg.c` | libjpeg | `/usr/lib/libjpeg.a` ✅ | **必须**（已内置） |
| GIF | `loader_gif.c` | giflib | **缺失**（需 `apk add giflib-dev`） | 高 |
| BMP | `loader_bmp.c` | 无 | — | 高 |
| TIFF | `loader_tiff.c` | libtiff | `/usr/lib/libtiff.a` ✅（链 zstd/lzma） | 中 |
| WebP | `loader_webp.c` | libwebp | `/usr/lib/libwebp.a` ✅ | 中 |
| XPM/ICO/PNM/XBM | `loader_xpm/ico/pnm/xbm.c` | 无/少 | — | 低 |

#### 1.2.2、怎么支持（同 xlunch 内置 loader 机制）

对每个需要的 loader 源，用宏**重命名符号**编译成静态对象，补丁 `loaders.c` 内置注册，`ar` 进 `libImlib2.a`：

1. **宏重命名编译**（避免多 loader 符号冲突）：
   ```sh
   xx-clang -Os -fomit-frame-pointer -DHAVE_CONFIG_H $INC \
     -Dload2=jpeg_load2 -Dsave=jpeg_save -Dformats=jpeg_formats \
     -c loader_jpeg.c -o /tmp/builtin/jpeg.o
   ```
2. **补丁 `loaders.c`** 的 `__imlib_LoadAllLoaders` 内置块：为每个格式加 `extern X_load2/X_save/X_formats` + `malloc(ImlibLoader)`（`file="jpeg"`…）+ 直连 `load2/save/formats` + 串成链表（`png->next=svg->next=jpeg->…`）。
3. **`ar r libImlib2.a`** `loaders.o png.o svg.o jpeg.o gif.o bmp.o …` + `ranlib`。
4. **feh 链接补依赖**：`-Wl,--start-group` 包 `-lImlib2 -lrsvg-2 -lcairo … -ljpeg -lgif -ltiff -lwebp -lpng … -Wl,--end-group`（同 xlunch）。
   - GIF 先 `apk add giflib-dev`（`libgif.a`）。
   - TIFF 静态链需 `-lzstd -llzma`（无 libzstd 则过滤，tiff 非必需）。

#### 1.2.3、注意（承接 xlunch 结论）

- 原始 `loaders.c` **无内置块**，补丁须**整体插入**（锚点 `if (loaders)\n      return;`），不能只加单个。
- `im->format` 不能设字面量（imlib2 自动 `strdup`，失败清理 `free` 会崩）。
- 内置 loader 依赖静态库须在 `b_deps` 就位（`librsvg-2.a` 无 apk 静态子包，须本地编译 v-tint2 librsvg）。

## 二、开工评估与计划

### 2.1、只支持"必须"格式（png/svg/jpeg），补 JPEG 内置 loader

- **范围收敛**：只支持"必须"的 **PNG、SVG、JPEG**；其余（gif/bmp/tiff/webp）暂不做。
- **现状**：PNG/SVG 已内置（11-05 xlunch 跑通）；**JPEG 需补**——`loader_jpeg.c` imlib2 核心自带，`libjpeg.a` 已装（`libjpeg-turbo-static-2.1.2`），`jpeglib.h` 在 `/usr/include`。
- **步骤**（复制 png 模式第 3 个，机制已成熟）：
  1. `b_deps` 确保 `apk add libjpeg-turbo-static jpeg-dev`（已装，幂等）。
  2. `v-xlunch` `imlib2()` 内置段：python 补丁 `loaders.c` 加 `extern jpeg_load2/jpeg_save/jpeg_formats` + `bl3`（`file="jpeg"`）→ `bl2->next = bl3`（链表 png→svg→jpeg）；编译 `jpeg.o`（`-Dload2=jpeg_load2 -Dsave=jpeg_save -Dformats=jpeg_formats`）；`ar r libImlib2.a loaders.o png.o svg.o jpeg.o`。
  3. 验证 `imlibtest` 加载 JPEG `LOADED WxH`。
  4. `v-feh/build.sh`：`feh()` 链接补 `-ljpeg`（入 `--start-group`）；`b_deps` 确保 jpeg 静态。
  5. hdmi 实测：新 libImlib2.a 重链 feh，Xvnc JPEG 壁纸 `--bg-fill` 截图验证。
- **工作量**：小（约 30-60 分钟，含验证/截图/文档）；无新源码（用 imlib2 自带 `loader_jpeg.c`），`loaders.c` 补丁须整体插入。
- **改动文件**：`compile/src/v-xlunch/build.sh`、`compile/src/v-feh/build.sh`、`docs/2026/261105-v-feh.md`（1.2 更新）。

### 2.2、实现与验证结果（11-05 完成）

- **JPEG 内置 loader**：`v-xlunch/build.sh imlib2()` 内置段补丁 `loaders.c` 加 `jpeg_load2/jpeg_save/jpeg_formats`（`bl3` `file="jpeg"`，`bl2->next=bl3`），编译 `jpeg.o`，`ar r libImlib2.a loaders.o png.o svg.o jpeg.o`。`nm libImlib2.a` 见 `png_load2/svg_load2/jpeg_load2`。
- **imlibtest 验证**：PNG `LOADED 1x1`、SVG `LOADED 48x48`、JPEG `LOADED 8x8`。
- **v-feh/build.sh 链接修复（关键，三连坑）**：
  1. **链接错库**：feh 默认链 `/usr/lib/libImlib2.a`（旧版，443K，无内置 loader）→ 必须 `LDFLAGS="-static -L/usr/local/lib …"` 指向新 `libImlib2.a`（611K，带内置 loader）。
  2. **`-ljpeg` 放错位置**：简单 `sed 's^-lXi^-lXi -ljpeg^g'` 会把 `-lXinerama` 打断成 `-ljpegnerama`（子串误匹配）→ 必须把 `-ljpeg` 放进 `deps3` 变量整体注入。
  3. **SVG 依赖缺失**：`-lImlib2` 之后必须补 librsvg 链，否则 `rsvg_handle_render_cairo/cairo_set_operator/g_object_unref` 等未定义。用 `pkg-config --static --libs librsvg-2.0 cairo pangocairo`（过滤 `-lzstd -ltiff`）得到 `RSVG_LIBS`，**外加 `-lcroco-0.6`**（`cr_*` 符号，librsvg 未声明依赖，pkg-config 不列出），整体包 `-Wl,--start-group -lImlib2 $deps1 $deps2 $deps3 $RSVG_LIBS -lxml2 -lcroco-0.6 -Wl,--end-group`。
  - 注：feh `src/Makefile` 链接规则 `${CC} ${LDFLAGS} ${CFLAGS} -o $@ ${OBJECTS} ${LDLIBS}`，**`LDLIBS`（config.mk，sed 注入）在对象之后**才解析符号；`LDFLAGS` 里的 `-L/usr/local/lib` 全局生效（`-lImlib2` 优先命中新库）。
- **产物**：`/tmp/fk-feh/src/feh` **37.8M** 静态（`ldd` 报 "Not a valid dynamic program"，确认静态）；`nm` 见 `png_load2/svg_load2/jpeg_load2` + 对应 `formats`。
- **hdmi 实测（Xvnc `:462`）**：`/tmp/feh-new --bg-fill` 对 PNG/SVG/JPEG 三种壁纸均 `exit=0`；scrot 截图 1280x800 逐格式采样验证：
  - PNG：深色内容 `(18,20,25)`；
  - SVG：精确命中测试色——背景 `#2e8b57`(46,139,87)、圆 `#ffd700`(255,215,0)；
  - JPEG：照片内容（130 个不同色采样，非空白）。
  - 截图存 `docs/img/tmp/v-feh/wall-{png,svg,jpg}.png`（配 `test.{png,svg,jpg}`）。

### 2.3、踩坑/注意项汇总（实现→调试→e2e 全程）

**实现（JPEG 内置 loader）**
1. `loaders.c` 原本**无内置块**，补丁须**整体插入**（锚点 `if (loaders)\n      return;`），不能只加单个 loader。
2. `im->format` 不能设字面量（imlib2 自动 `strdup`，失败清理 `free` 会崩）。
3. 编译 `jpeg.o` 需 `jpeglib.h`（`jpeg-dev`），链接需 `libjpeg.a`（`libjpeg-turbo-static`），且须在 `v-xlunch imlib2()` **之前**装好（`b_deps` 顺序，`jpeg.o` 编译期就用头）。
4. `loader_jpeg.c` 是 imlib2 自带，无新源码；补丁链表 png→svg→jpeg（`bl2->next=bl3`）。
5. 内置 loader 依赖静态库须在 `b_deps` 就位（`librsvg-2.a` 无 apk 静态子包，须本地编译 v-tint2 librsvg）。

**调试（feh 静态链接）**
6. **链接错库**：feh 默认链 `/usr/lib/libImlib2.a`（旧版无内置 loader）→ 必须 `LDFLAGS="-static -L/usr/local/lib …"` 指向新库。
7. **`sed` 子串误伤**：`sed 's^-lXi^-lXi -ljpeg^g'` 会把 `-lXinerama` 打断成 `-ljpegnerama`（`-lXi` 是 `-lXinerama` 前缀）→ `-ljpeg` 必须放进 `deps3` 变量整体注入。
8. **SVG 依赖缺失**：`-lImlib2` 后必须补 librsvg 链，否则 `rsvg_handle_render_cairo/cairo_set_operator/g_object_unref` 未定义。
9. **`-lcroco-0.6` 必须手动加**：librsvg 未声明 croco 依赖，`pkg-config librsvg-2.0` **不列出**，但 `rsvg-styles.o` 需 `cr_*` 符号（`cr_rgb_set_from_name/cr_selector_ref` 等 412 个）→ 漏掉报 `undefined reference to cr_rgb_set_from_name`。
10. **循环引用**：rsvg↔cairo↔glib↔pango 互相依赖 → 整体包 `-Wl,--start-group -lImlib2 … -Wl,--end-group` 才能一次解析。
11. **`pkg-config --static` 带多余缺库**：`gdk-pixbuf` 非必需 io 的 `-lzstd -ltiff` 无静态库 → `grep -vE '^-l(zstd|tiff)$'` 过滤。
12. **feh 链接规则顺序**：`src/Makefile` `${CC} ${LDFLAGS} ${CFLAGS} -o $@ ${OBJECTS} ${LDLIBS}`——`LDLIBS`（config.mk，sed 注入）在**对象之后**才解析符号；`LDFLAGS` 里 `-L/usr/local/lib` 全局生效。

**e2e（hdmi Xvnc `:462`）**
13. **DISPLAY 不对**：hdmi 容器默认 `DISPLAY=:1`（pid1 环境），目标 Xvnc 是 `:462` → 测试须 `export DISPLAY=:462`。
14. **静态确认**：`ldd feh` 报 "Not a valid dynamic program"（确认静态）；`nm feh | grep load2` 看内置 loader 是否真正链入（而非只编译了）。
15. **测试素材**：壁纸须 `docker cp` 进容器；用 `--bg-fill` 设根窗口。
16. **`scrot` 偶发挂起/漏图**：首跑可能未生成文件 → 用 `timeout 10 scrot` 重跑；截图需匹配 Xvnc geometry（1280x800）。
17. **像素采样防误判**：用 PIL 解码采样确认非黑屏/非空白——SVG 精确命中测试色（`#2e8b57`/`#ffd700`）、JPEG 130 个不同色（照片）、PNG 深色 `(18,20,25)`。

> **效果截图**：`docs/img/tmp/v-feh/wall-combo.png`（三格式并排对比，1472x352）。
