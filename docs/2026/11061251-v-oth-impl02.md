#### 1.2、三个坑（均已修进 build.sh）

1. **头文件目录**：dbus-glib 头须装 `libdbus_glibdir = $(includedir)/dbus-1.0/dbus/`（与 dbus 头同目录）。
   dbus-glib.h 内部 `#include <dbus/dbus-gtype-specialized.h>`（`<dbus/...>` 形式），pc Cflags
   `-I${includedir}/dbus-1.0` 即解析；消费者 `#include <dbus/dbus-glib.h>`。误装 `dbus-glib/` 报
   `dbus/dbus-gtype-specialized.h: file not found`。
2. **pc Requires 漏 gio-2.0**（上游 bug）：configure 检测 gio>=2.40，但 dbus-glib-1.pc 的 Requires 只列
   `dbus-1 glib-2.0 gobject-2.0`。libdbus-glib-1.a 引 `g_dbus_is_member_name`（gio），静态链报
   `undefined reference` → 安装时 sed 补 `Requires: ... gio-2.0`。
3. **dbus-1.pc 的 Libs 行**（非 Libs.private）须补 `-lexpat -lpthread -ldl -lm`：dbus-glib configure 的
   PKG_CHECK_MODULES(DBUS) 用 `pkg-config --libs dbus-1`（非 `--static`），只读 Libs 行；只补
   Libs.private 不够，configure 链接测试失败。

### 4、exo/garcon GTK3 硬依赖坑（→ 用 GTK2-only 老版 2026-11-06）

#### 4.1、发现（builder-obox 实测）

- ❌ **exo 0.12.5/0.12.3/0.12.1/0.11.5 全部硬依赖 gtk+-3.0**：configure.ac 里
  `XDT_CHECK_PACKAGE([GTK], [gtk+-2.0]...)` + `XDT_CHECK_PACKAGE([GTK3], [gtk+-3.0], [3.22.0/3.20.0])`
  都是**必需**；`--disable-gtk3` **无效**（gtk3 check 无 if 门）。exo 0.12.5 configure 实测报
  `The required package gtk+-3.0 was not found`（即使 gtk2 2.24.33 已检测通过）。
- ❌ **garcon 0.6.4/0.5.0 也硬依赖 gtk+-3.0 + libxfce4ui-2**（GTK3 版 libxfce4ui）：configure.ac
  `XDT_CHECK_PACKAGE([GTK3], [gtk+-3.0], [3.20.0])` + `XDT_CHECK_PACKAGE([LIBXFCE4UI2], [libxfce4ui-2], [4.12.0])`
  **必需**；GTK2 版 `garcon-gtk2-1.pc` 只是**可选**（需 gtk2 + libxfce4ui-1 同真才产）。
- ⚠️ 本项目 GTK2-only（无 gtk3），故 4.12 系 exo/garcon 的 GTK2 子库**无法直接建**——v-oth 六章
  选 exo 0.12.x/garcon 0.6.x 的假设**不成立**，须改用 GTK2-only 老版。

#### 4.2、解决（GTK2-only 老版）

- ✅ **exo 0.10.6**（2014）：configure.ac 仅 `XDT_CHECK_PACKAGE([GTK], [gtk+-2.0], [2.24.0])`，
  无 gtk3 行 → GTK2-only；提供 `exo-1`（0.10.6 ≥ 0.7.1，满足 xfce4-settings 4.12.4 要求）。
- ✅ **garcon 0.4.0**（2012）：configure.ac 仅 `XDT_CHECK_PACKAGE([GTK2], [gtk+-2.0], [2.24.0])`，
  无 gtk3 行 → GTK2-only；提供 `garcon-1`（0.4.0 ≥ 0.1.10，满足 xfce4-settings 4.12.4 要求）。
- ✅ **验证通过（2026-11-06）**：exo 0.10.6 / garcon 0.4.0 用现 libxfce4util 4.12.1 +
  libxfce4ui 4.12.1 均 configure/链接/安装成功（详见第 5 节）。

#### 5.6、GtkBuilder 静态链类型注册坑（2026-11-06 发现并解决）

- **症状**：4 个二进制（appearance/keyboard/mouse/accessibility）GUI 加载报
  `Invalid object type 'GtkHScale'/'GtkCellRendererPixbuf'` 后退出；display/settings-manager/
  settings-editor/find-cursor 正常。
- **根因**（实测探针 + GTK2 源码 `gtkbuilder.c` 确认）：`gtk_builder_real_get_type_from_name`
  先 `g_type_from_name()`（**惰性注册**，需先调 `*_get_type()`），失败再 `_gtk_builder_resolve_type_lazily()`
  （`g_module_symbol(NULL,...)` **dlsym**，纯静态 ELF **无 .dynsym** → 必然失败）。
- **⚡ 关键**：`gtk_xxx_get_type()` **未接收返回值时被 `-O2`+gc-sections 优化掉** → 类型未注册。
  探针实测：`gtk_cell_renderer_pixbuf_get_type();`（弃值）→ `g_type_from_name` 仍 NOT；
  `GType t = gtk_cell_renderer_pixbuf_get_type(); (void)t;` → **REGISTERED**。
- **解法**：各二进制 **builder 加载前** 对 glade 用到的所有类型
  `{ GType _t = gtk_xxx_get_type (); (void)_t; }` 强制注册（keyboard 另需
  `xfce_titled_dialog_get_type`；mouse/accessibility 已有 `xfce_titled_dialog_get_type () == 0`
  hook 故免加）。改 `main.c`/`xfce-keyboard-settings.c` 重编重链（4 个二进制 +~4K）。
- **验证**：修后 4 个二进制 GUI 全过（第 5 节 5.5 表）。

#### 5.8、静态无中文（gettext LOCALEDIR 坑）——同 engrampa/lxtask/pcmanfm，2026-11-06 确认

**现象**：v2 截图界面英文（窗口标题 "Settings"），但系统 locale 为 zh_CN；用户提示
"之前处理过 pavucontrol"，从该历史找借鉴。

- **根因（确凿）**：二进制 `strings` 含 `LOCALEDIR=/usr/local/static/xfce4settings/share/locale`
  （+ libxfce4ui/libxfce4util 的 `/usr/local/static/xfce/share/locale`）——**gettext 编译期

### 9、xfce4-display-settings 免 xfsettingsd/xfconf 直接应用 + 其余二进制屏蔽（2026-11-08）

> 用户要求：xfce4-display-settings 点"应用"**直接**改 RandR 生效（免 xfsettingsd 中转），
> 且**不依赖 xfconf daemon**（无 daemon 时降级不崩溃）；同时 xfce4-settings 只保留
> display-settings 一个二进制（**xfsettingsd 亦不生成**，其余 8 个屏蔽）。承接 check01
> `docs/2026/11080050-v-oth-check01.md` 二章 1 节（分析 A/B/C）。

#### 9.1、失效机制（源码实证，4.12.4）

- **`xfce_randr_apply()`**（`dialogs/display-settings/xfce-randr.c`）原实现**只**写 xfconf
  `displays` 通道 `/Schemes/Apply`（`xfconf_channel_set_string`），真正应用靠 **xfsettingsd**
  `displays.c` 的 `xfce_displays_helper_apply_all()`→`XRRSetCrtcConfig`——故无 xfsettingsd 时
  "应用"无效。
- **main.c**：`xfconf_init()` 失败 → `g_error("Failed to connect to xfconf daemon")` + 直接
  `return EXIT_FAILURE`（**fatal**）——无 xfconf daemon 时二进制直接退出。
- **组合框 `can_focus=False` 且无 `mnemonic_widget`**：`display-dialog_ui.h` 内嵌 XML 里
  resolution/refresh/rotation/reflection 四个组合框 `can_focus=False`，label（如 `R_esolution:`）
  有 `use_underline` 但**未绑定 `mnemonic_widget`**→ Alt+R 不聚焦组合框，键盘改分辨率不可行
  （GUI 自动化需鼠标）。

#### 9.2、实现

- **补丁 `compile/src/v-xfce4/xfce4settings-xfconf-free.patch`**（206 行，`patch -p1` 可净应用，
  改 2 文件）：
  - **xfce-randr.c**：
    - `XfceRandrPrivate` 新增 `guint *output_ids`（记录 output m → `resources->outputs` 索引，
      `xfce_randr_populate` 里 `g_memdup2` 保存）——直接应用需按索引回查 output id。
    - 新增 `static void xfce_randr_apply_native(XfceRandr*)`：逐开启 output（`mode[m]!=None`）
      用 `output_info[m]->crtc` + `mode[m]/position[m]/rotation[m]` 调
      `XRRSetCrtcConfig(...,&out_id,1)`，末 `XFlush`——**免 xfsettingsd 中转**。
    - `xfce_randr_apply()` 改为：先 `xfce_randr_apply_native(randr)`；若 channel 可用再写
      `/Schemes/Apply`（兼容，落 xfconf 时仍通知）。
    - `xfce_randr_populate()` 的局部 `xfconf_channel_new("displays")` 改为**仅 `xfconf_ok` 时建**
      ——否则 init 失败时 `channel_new` 返回**非 NULL 坏对象**（`XFCONF_IS_CHANNEL` 仍过），
      后续 `xfconf_channel_set_*` 崩溃（实测 SIGSEGV rc=139）。
    - `xfce_randr_save_output()` 开头 `g_return_if_fail(XFCONF_IS_CHANNEL)` 改
      `if(channel==NULL||!XFCONF_IS_CHANNEL(channel)) return;`（容忍 NULL）；populate 里调用加
      `if(display_channel!=NULL)` 保护。
  - **main.c**：
    - `gboolean xfconf_ok`（去 `static`，供 xfce-randr.c `extern`）；`xfconf_init` 失败改为
      `g_warning("xfconf daemon not available (%s); running without config storage")` +
      `display_channel=NULL` **继续**（原 `g_error`+exit 删除）。
    - `xfconf_g_property_bind` 加 `if(display_channel!=NULL)` 保护；cleanup `g_object_unref`
      NULL 安全；`xfconf_shutdown` 仅 `xfconf_ok` 时调。
- **`compile/src/v-xfce4/build.sh`**：`make`/`link_bin`/`verify` 三处**只留
  `dialogs/display-settings`→`xfce4-display-settings`**（删 xfsettingsd 与其余 8 个的
  make/link/verify）；`xfce4settings()` 接入 xfconf-free patch（`grep xfce_randr_apply_native`
  判已应用）。

#### 9.3、验证（builder-awe 重编 + hdmi `docker-hdmi-desktop-desktop-1` Xvnc :561）

> 按 AGENTS.md §3.1：独立 Xvnc（:561，`-SecurityTypes None -localhost -ac -geometry 1280x800
> -depth 24`），用后清 lock/socket；**无 xfconf** 用 `DBUS_SESSION_BUS_ADDRESS=unix:path=/tmp/

- **改前对照（无 patch 旧二进制）**：无 xfconf → `g_error("Failed to connect to xfconf daemon:
  ...")` + `Trace/breakpoint trap`（rc=133）——即原 fatal 行为，佐证 9.1。
- **patch 后**：无 xfconf → 仅 `WARNING: xfconf daemon not available (...); running without
  config storage`，GUI **正常启动**（窗口 "Display" 530x368 出现、进程常驻、无崩溃）——

  `XRRSetCrtcConfig` 调用）：`VNC-0` 1280x800 → **800x600**（`Status=OK`，`xrandr` 确认

- **产物**：`xfce4-display-settings` **14.8M** `statically linked, stripped`（xx-verify PASS）；

- ⚠️ **局限**：裸 Xvnc（无 WM）下 GTK 组合框 popup 不渲染（鼠标点击不弹下拉），**GUI 自动化
  "点击应用"未能端到端**；apply 路径以 applytest 静态探针（X 层）+ 代码审查（apply_native 为

### 候选窗显示优化记录（v2→v5，含踩坑/注意项）

**调整过程**：v2 白底黑字 → v3 初版深色 → v4 精修色（Greybird-dark 精确值）+ EventBox
选中行 → v5 ARGB 圆角 + 亮蓝选中 → 最终圆角定 2px。

**踩过的坑**：
- `GtkLabel` **不绘制背景**：`gtk_widget_modify_bg` 对 label 无效（透明 widget），选中行蓝底
  从未真实显示（v3 分析 blue 仅 3px，是文字抗锯齿）。→ 选中行用 **`GtkEventBox`** 包裹 +
  `gtk_box_pack_start(box, eb, FALSE, TRUE, 0)`（fill=TRUE 整行高亮）。
- **`GdkRGBA` 是 GTK3 类型**：GTK2 用 `GdkColor` 16 位通道，cairo 需 `color.red/65535.0` 转 double。
- **`gtk_widget_get_allocated_width/height` 是 GTK3**：GTK2 用 `gtk_widget_get_allocation` + `alloc.w/h`。
- **ARGB 圆角需 compositor**：`gdk_screen_get_rgba_visual` + `gtk_widget_set_visual` +
  `gtk_widget_set_app_paintable` + `expose-event` cairo 圆角，**依赖 xcompmgr + Composite 扩展**
  （hdmi 有 xcompmgr 419282）；无 compositor 时 ARGB 角落会变黑（不透明）。
- **深色下候选 label 必须设浅色 fg**：原默认黑字在 `#2d2e30` 深底不可见。

**注意项**：
- 候选窗渲染前提：**`cand_vbox` 必须 show**（GTK2 父容器不 show 则子控件不绘制）；
  `_panel_show_candidates` 需在 show `cand_win` 前 `gtk_widget_show(cand_vbox)`。
- 选中蓝用 Greybird-dark `selected_bg_color` = **`#398ee7`**（勿用 #145ba6 偏深）。
- 圆角半径经 `PANEL_ROUND` 环境变量运行时调（默认 2px，编译期 `#define PANEL_ROUND`）。
- panel 重启命令：`setsid bash -c 'sudo -u headless bash -c "export DISPLAY=:1; ...; exec
  /usr/local/static/ibus/libexec/ibus-panel > /tmp/panel_X.log 2>&1 < /dev/null"' < /dev/null > /dev/null 2>&1 &`。
- build.sh 的 `panel()` 需**自包含**（pkg-config ibus-1.0 头 + `/usr/local/static/ibus/lib/libibus-1.0.a`），
  不依赖已消失的 `/tmp/ibus` 构建树。
- 图片按用户要求：保留多版本（v2/v3/v4/v5 及 2/3/4px 变体）、文档不内嵌图、图片/源码/文档分开 commit。
