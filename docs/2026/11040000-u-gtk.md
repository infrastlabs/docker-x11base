## 二、主题免环境变量机制（重点）

- **两层**：
  1. **引擎内置**（murrine + pixmap 在 `builtin_theme_engines[]`，`gtk_theme_engine_load` 先查内置表）
     → 免 dlopen 引擎 `.so`；
  2. **主题目录宏** `GTK_DATA_PREFIX="/usr"`（`gtkrc.o`，`gtk_rc_get_theme_dir` 不设变量也返回
     `/usr/share/themes`）→ 免设 `GTK_DATA_PREFIX` 环境变量。
- **两者齐备** → GTK2 应用**无需设 `GTK_DATA_PREFIX`、无需系统引擎 `.so`** 即有 Greybird 主题。
- **前提**：`--prefix=/usr`（`gtk()` configure）+ patch 版 `gtkthemes.o`（builtin 表 murrine+pixmap）。
- 引擎模块 `.so` 若系统路径为 multiarch（`/usr/lib/x86_64-linux-gnu/gtk-2.0/...`）而 GTK2 找
  非 multiarch（`/usr/lib/gtk-2.0/...`）→ 不内置则必失败（builtin 是唯一可靠解）。

## 六、增量构建加速（缓存复用）

### 1、思路（2026-11-08 确认，待优化 `u-gtk/build.sh`）

> 调试场景频繁构建，`gtk()` 每次全量 `rm -rf /tmp/gtk` + clone + autogen + configure +
> make gdk/gtk + murrine + pixmap + ibus，改一个 patch 也全重来（20-40min）。目标：
> **增量友好**——首次全量，后续只重编改动的对象。

**① 源码树缓存（保留 `/tmp/gtk`，不每次 clone）**
- 若 `/tmp/gtk/.git` 存在 → **不 clone**，`git -C /tmp/gtk checkout --force <branch>`（丢弃
  patch/改动，回干净 HEAD）+ 重新打 patch。
- 省下载 30MB + 解压。

**② build 产物增量复用（保留 `.o`，`make` 自动增量）——最大头**
- **不删** `/tmp/gtk/gtk/.libs/*.o`、`gdk/.libs/*.o`，保留构建目录。
- 只改某 patch → `git checkout` 还原该文件 → 重新 `patch` → `make -C gtk xxx.lo`
  **只重编该 .o**（make 时间戳增量），其余复用。
- make 自带时间戳：`.c` 比 `.o` 新才重编。

**③ configure 缓存**
- `config.status` 已存在且参数没变 → **跳过 configure**（省 ~5min）。
- 参数变了 → 删 config.status 重跑（make 检测 config.h 变化增量重编）。

**④ murrine / ibus 缓存**
- `/tmp/murrine` 保留（`[ -d ] || git clone`），make 增量；`gtk_ibus_a2` 的
  `IBUS_BUILD=/tmp/ibus` 已存在则复用。

**⑤ patch 幂等（保证可重复）**
- 靠 `git checkout --force` 还原后再 patch，避免 "already applied"；或 `git apply --check`。

**风险与规避**
- 源码树污染 → `git checkout --force` + `git clean`（仅源码文件，不清 `.libs`）。
- configure 参数变更失效 → 检测 `config.status` 或存参数字符串对比。
- patch 影响文件需精确还原 → 全源码 checkout 还原再全打 patch（patch 快，损失小）。
- **避免 `.a` 手动改**（守则2）→ 统一 `make -C gtk` 产出完整库 + 合并 murrine/pixmap/ibus。

**预期**：首次全量（~30-40min）不变；后续改单 patch 增量**秒级~1min**（只重编该 .o +
合并进库）；改 configure 参数分钟级（增量重编受影响对象）。

### 2、实现 + 验证（2026-11-08 已提交 2456f9e / 652ad60）

**实现（`u-gtk/build.sh` gtk() 重写，含 `inc_patch()` 助手）**
- **① 源码树缓存**：`/tmp/gtk` 已有 `.git`+`config.status` → 复用（不 clone）；否则全新 clone。
- **② patch 增量**：`inc_patch <patch> "<files>"` 按 **patch 内容 sha256** 判定：
  - 未变 → 跳过（文件 mtime 保持 → `make` 时间戳增量复用 `.o`，只重编该 patch 触及的 .o）。
  - 变更 → 先 `git checkout --force -- <files>` 还原到 HEAD，再 `patch -p1` 重打。
  - 各 patch 触及文件**不相交**（已核：gtkthemes/gtkmain/gtkmodules/gtkprintbackend/
    pixbuf-main/Makefile.am/gtkprintbackend{file,lpr}/gtkbuilder），可独立处理无冲突。
- **③ configure 缓存**：SIG = sha256(printbackends patch + CONFIG_ARGS)；`config.status` 存在
  且 SIG 匹配 → 跳过 autogen+configure。Makefile.am 补丁(printbackends)变更才需重新生成
  Makefile.in，只改 .c 的补丁不需要。
- **④ murrine 缓存**：`/tmp/murrine` 已有 `.git`+`config.status` → `make` 增量；否则 clone+configure。
- **⑤ ibus**：`gtk_ibus_a2` 的 `IBUS_BUILD=/tmp/ibus` 存在则复用（未改，保持原逻辑）。
- **safe.directory**：树可能由 host/另一容器拷入（属主 1000 非 root）→ git 报
  `dubious ownership` (rc=128) 致 checkout 失败。对 `/tmp/gtk`、`/tmp/ibus`、`/tmp/murrine`
  统一 `git config --global --add safe.directory`。

**验证（builder-awe，种子自 builder-obox 完整树 267M：有 .git+260 .o+config.status）**
- `inc_patch` 首次：4 patch 全部 APPLY（checkout 还原→patch 重打），gtkthemes 含 murrine、
  gtkprintbackend 含 builtins 均确认。
- `inc_patch` 二次（STATEDIR 已存 hash）：4 patch 全部 SKIP，文件 mtime 保持（make 复用 .o）。
- configure-skip：首次（无存储 SIG）CONFIGURE；二次 SKIP。✓
- murrine：`.git`+`config.status` 在 → REUSE。✓
- 环境坑（非逻辑）：**builder-awe 无出站网络**（DNS 可达、https 出阻断）→ 无法 git clone，
  需宿主机/另一容器(obox)下载后 `docker cp` 种子。宿主 `/tmp` 对 headless 可写（用项目目录中转
  更稳）。**docker exec 跨容器 tar 流不靠谱**（short read），必须 host 中转。
- ⚠️ **未完成**：全量端到端构建未跑（`gtk_ibus_a2` 需 `/tmp/ibus` 为**已 configure** 树才能
  `make -n` 捕获编译命令；当前 awe 的 /tmp/ibus 是 pristine 未 configure → A2 会失败 abort）。
  增量逻辑本身已全部验证，A2 是前置环境问题，与本次增量改动无关。
